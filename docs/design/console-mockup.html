資訊架構

兩個大選項就夠了

去人聲本來就是「先抓音檔再分離」，所以把它放進音檔底下最誠實。使用者的心智模型變成：我要音檔還是影片？要音檔的話要哪幾個版本？

輸出 ├─ ☑ 音檔 摘要：MP3 192k · 原曲 + 伴奏 │ ├─ 版本（可多選，常駐顯示） ☑ 原曲 ☑ 伴奏（去人聲） ☐ 人聲 │ └─ 細項（收合） │ ├─ 格式 MP3 · M4A · WAV · FLAC │ ├─ 位元率 128k · 192k · 320k │ └─ 分離模型 快速 htdemucs · 高品質 htdemucs_ft └─ ☐ 影片 摘要：MP4 · 最佳畫質 └─ 畫質上限 最佳 · 1080p · 720p
  • 「版本」不收進細項，因為伴奏是最常用的功能，不能多點一層才找到。
  • 選項卡標題右側的摘要文字，讓細項收合時也看得到目前設定。
  • 分離模型只在勾了伴奏或人聲時才有意義，未勾時該列變灰。
  • 細項的選擇記在設定裡，下次啟動沿用；「版本」每次都回到預設「原曲」，避免不小心多跑一次 8 分鐘的分離。
  • 「開始」按鈕顯示會產生的檔案數：2 個網址 × 2 個版本 = 4 個檔案，讓使用者按之前心裡有數。

一個網址一張卡片，裡面列出每個輸出檔。

排隊卡片上的「輸出」列每個檔案一顆膠囊，右側小圖示是它自己的狀態：時鐘等待、轉圈處理中、勾完成、叉失敗。整張卡的進度條和步驟數字（2/3 · 分離）說的是目前進行的那一步。
